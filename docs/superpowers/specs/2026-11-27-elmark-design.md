# ELmark 设计文档

> 日期：2026-11-27  
> 状态：已确认

## 1. 背景与意图

当前 `ELmark` 是一个全新的空仓库（仅包含 `.git` 与 `LICENSE`）。

**为什么要做这个项目**：
- Typora 已经转为付费软件，日常使用存在门槛。
- 现有的开源 Electron 替代品（如 MarkText）在实际使用中体验明显不如 Typora，核心痛点集中在两点：
  1. **界面质感差**：缺乏 Typora Light 那种简约、克制、统一的阅读美学。
  2. **所见即所得交互突兀**：在 Markdown 格式渲染与光标定位上不够自然统一（例如点击标题或框选文字时，格式标记突然展开导致文字水平位移，破坏阅读和选区连贯性）。

**核心目标**：使用 Node.js + Electron，以尽量轻巧、可控的开发成本，构建一个免费、不侵权、在各种日常 Markdown 阅读与顺手编辑场景下都能真正用起来的桌面工具。

---

## 2. 目标、非目标与反目标

### 目标（Goals）

1. **Typora Light 级极简统一视觉**
   - 简约浅色风格，Windows 端采用一体化极简单顶栏，高可读性的排版留白与克制的界面元素，避免一切多余装饰。
2. **自然、稳定、不跳动的所见即所得体验**
   - 块级元素采用结构化渲染；6 级标题层次清晰合理——前 3 级标题（H1–H3）通过底部画线与正文明确区分，后 3 级标题（H4–H6）通过字号与字重自然过渡。
   - 用户可以在任意位置点击、移动光标或跨段选择标题与正文，不会出现原始 `#` 符号突然弹出导致文字左右位移的突兀感。
3. **适配真实日常 Markdown 阅读与编辑场景（V1 能力清单，按优先级排序）**
   - **基础能力（必需前提）**：
     - 标准 CommonMark + GFM 的所见即所得阅读、编辑与保存（6 级标题、段落、行内格式、有序/无序/任务列表、引用、分割线、带语法高亮的代码块、本地相对/绝对路径及网络图片渲染）。
     - **真实文档兼容**：无损保留 YAML Frontmatter（`---` 头部元数据），并安全渲染常见阅读类原生 HTML 标签（如限宽 `<img>`、`<details>/<summary>` 折叠块、`<br>`、`<div align>` 等）。
     - **轻量源代码模式（`Ctrl+/`）**：支持与所见即所得视图一键互切兜底，同时为日常编辑提供极简微交互。
     - **轻量页内查找（`Ctrl+F`）**：支持在当前文档内快速检索定位。
   - **P1：大纲与文件树侧边栏**：支持打开本地文件夹浏览目录树与切换 `.md` 文件，支持基于当前文档实时生成多级大纲并点击跳转。
   - **P2：Mermaid 流程图**：支持渲染 `mermaid` 代码块为清晰图表，并支持在阅读态与代码编辑态之间平滑切换。
   - **P3：表格**：支持 GFM 表格的创建、所见即所得展示与基础编辑。
   - **P4：导出 PDF**：将当前文档按接近阅读视图的排版质感导出为 PDF 文件。

### 非目标（Non-Goals，V1 不做）

- 不做文档内全局替换（`Ctrl+H`）。
- 不做账号系统、云同步或多人实时协作。
- 不做插件市场或复杂多主题商店（V1 专注打磨好一套默认 Typora Light 风格浅色主题）。
- 不做 LaTeX / KaTeX 数学公式渲染（不在本轮刚需内，架构层面不阻断未来扩展）。
- 不做图床自动上传管理（仅负责正确解析与显示本地及远程图片）。
- 不做多标签页浏览器式界面或复杂分屏（**[设计建议]** V1 采用 Typora 同款单窗口单文档 + 可折叠侧边栏，如需同时看两篇可多开窗口，避免 UI 变重）。
- 不做跨平台应用商店签名与自动更新服务器（V1 优先保障本地可运行的 Windows 桌面端）。

### 反目标（Anti-Goals，出现即视为失败）

- **禁止 MarkText 式的光标跳动**：点击或框选标题及其他块级元素时，绝不允许因强行展开原始 Markdown 符号造成排版水平跳动。
- **禁止视觉廉价感与 UI 堆砌**：不引入 Notion 式的左侧悬浮拖拽句柄、常驻顶部富文本大工具栏、多层原生菜单叠加或花哨彩色控件干扰阅读。
- **禁止版权侵权**：不复制、逆向或搬运 Typora 的源码、私有样式表、图标或专有字体，所有界面与排版样式均为独立编写，依赖均为合规开源协议。
- **禁止静默损坏原文件头部元数据**：打开并保存含 YAML Frontmatter 的 `.md` 文件时，绝不能把 `---` 头部错乱改写为分隔线或标题。

## 3. 约束条件

- **平台与运行时**：Electron + Node.js（当前本地环境 Node `v24.21.0`、npm `11.19.0`，首发面向 Windows 桌面端，保持跨平台兼容习惯）。
- **安全边界**：开启 `contextIsolation: true`，关闭 `nodeIntegration`；渲染原生 HTML 片段前必须经过严格净化（如 `DOMPurify`），防止本地恶意 `.md` 文件触发渲染进程 XSS；本地图片访问通过受控自定义协议限制边界。
- **开源合规**：所有第三方库须采用 MIT / Apache-2.0 / BSD / ISC 等宽松开源协议。
- **数据主权**：本地 `.md` 纯文本文件是唯一数据源，不引入私有数据库格式锁定用户文档。
- **工程复杂度**：坚持“简易开发”原则，不自研底层富文本编辑引擎，复用成熟内核把精力集中在体验和排版打磨上。

## 4. 内核方案对比与选型

前期已直接排除“从零手写 `contenteditable` + 自研解析器”（即 MarkText Muya 路线），因为中文输入法（IME）组合、跨块选区、撤销栈与表格光标维护成本极高，既违背简易开发也难以稳定超越 MarkText。

综合对比三条可行路线：

| 方案 | 原理 | 优势 | 代价 / 风险 |
| --- | --- | --- | --- |
| **方案一：Milkdown 无头核心（`@milkdown/kit`，ProseMirror + Remark）**（**已选定**） | ProseMirror 提供结构化块级编辑模型，Remark 负责与 `.md` 文件的原生 AST 双向转换；不使用带 Notion UI 的 Crepe，而是自写极简 Typora Light 样式层。 | 1. 块级节点原生稳定，彻底根治标题点击跳动；<br>2. Markdown 为一等公民，GFM 表格、大纲提取与 Mermaid 自定义节点视图贴合度最高；<br>3. 无头模式确保 100% 掌控极简界面质感，开发量可控。 | 保存 `.md` 时会按 Remark 规范做轻量格式化（如列表符号统一）；几万行级别超大文档的内存占用高于纯文本编辑器；需在 Remark/ProseMirror 层补充 Frontmatter 与受控 HTML 支持。 |
| **方案二：Tiptap（ProseMirror + Markdown 转换扩展）** | 同样基于 ProseMirror，但底层是 JSON/HTML 优先模型，通过外部扩展层与 Markdown 互转。 | 生态文档非常丰富，表格交互现成能力强。 | Markdown 非原生格式，复杂嵌套结构或自定义块（如 Mermaid）在双向序列化时容易产生多余转义或格式走样，需要额外维护转换补丁。 |
| **方案三：CodeMirror 6 实时预览（Obsidian 模式）** | 纯文本代码编辑器 + 装饰器隐藏非光标行的语法符号。 | 100% 逐字节保真原始 `.md`；虚拟滚动处理几万行大文件毫无压力。 | 光标落入标题行会展开原始 `#` 导致文字位移，表格所见即所得编辑体验别扭，与用户期望的 Typora 手感背道而驰。 |

**选定结论**：采用 **方案一（Milkdown 无头核心 + 自研 Typora Light 视图层）**，用户已明确拍板按该路线推进。

## 5. 架构与产品设计

> 说明：以下内容明确区分**用户已拍板的部分**与**设计建议（标注为 `[设计建议]`）**。

### 5.1 整体进程架构

采用标准 Electron 三层安全架构：

1. **主进程（Main Process，Node.js）**
   - **一体化窗口管理（用户决定）**：Windows 端采用 `titleBarStyle: 'hidden'` + `titleBarOverlay`（配色与浅色顶栏一致，复用 Windows 原生最小化/最大化/关闭按钮及高分屏缩放），支持单文档多开窗口并记住窗口尺寸。
   - **应用菜单弹出**：维护完整原生菜单定义（文件、编辑、插入、视图、导出 PDF 等），由顶栏极简菜单按钮通过 `Menu.popup()` 触发，同时全局注册快捷键。
   - **本地文件与目录树**：打开文件、打开文件夹、保存、另存为、支持系统“打开方式”或命令行参数传入 `.md` 路径直接打开；扫描目录树时自动忽略 `.git`、`node_modules` 等无关目录。
   - **受控本地图片协议**：注册自定义协议（如 `elmark-local://`）解析文档中的相对路径与绝对路径图片，既覆盖标准 Markdown 图片，也覆盖原生 HTML `<img>` 标签。
   - **页内查找桥接**：暴露 `webContents.findInPage` / `stopFindInPage` 及匹配计数回调给渲染进程。
   - **PDF 导出**：调用 `webContents.printToPDF()` 配合打印专用 `@media print` 样式表，通过系统保存框写出 `.pdf`。
2. **预加载脚本（Preload）**
   - 通过 `contextBridge` 暴露最小化、强类型的 IPC API（文件读写、目录树读取、弹出菜单、查找控制、PDF 导出、窗口状态同步、外部链接用系统默认浏览器打开）。
3. **渲染进程（Renderer）**
   - **[设计建议]** 采用 **TypeScript + React + Vite（配合 `electron-vite`）** 承载外壳 UI（一体化顶栏、侧边栏、查找条、轻量微交互浮层、双模式编辑器宿主）并挂载 `@milkdown/kit` 实例。

### 5.2 界面布局与 Typora Light 视觉基线

```text
┌─────────────────────────────────────────────────────────────┐
│ [☰] [◧]         document.md *                     ─  □  ×  │  一体化极简顶栏（可拖拽）
├──────────────────┬──────────────────────────────────────────┤
│  文件   │  大纲   │  ┌────────────────────────────────────┐ │
│ ────────┴─────── │  │ YAML Frontmatter (折叠，可点击查看) │ │  (仅存在时显示)
│ ▾ docs/          │  └────────────────────────────────────┘ │
│   ├ intro.md     │                                          │
│   └ guide.md     │   一级标题                                │
│                  │   ────────────────────────────────────   │
│                  │                                          │
│                  │   正文保持舒适阅读宽度（约 820px 居中），  │
│                  │   行高宽松、对比度柔和。                   │
│                  │                                          │
│                  │   二级标题                                │
│                  │   ────────────────────────────────────   │
│                  │                                          │
│                  │   三级标题                                │
│                  │   ────────────────────────────────────   │
│                  │                                          │
│                  │   四级标题（无底线，字号字重自然区分）      │
│                  │                                          │
│                  │   ┌─────────┐       ┌─────────┐          │
│ (可一键折叠隐藏)   │   │ Mermaid │ ────► │ SVG 图  │          │
│                  │   └─────────┘       └─────────┘          │
└──────────────────┴──────────────────────────────────────────┘
```

- **一体化极简顶栏（用户决定）**：
  - 高度克制（约 36–40px），支持拖拽移动与双击最大化（`-webkit-app-region: drag`，交互按钮设为 `no-drag`）。
  - 左侧仅保留「应用菜单按钮 `[☰]`」与「侧边栏显隐开关 `[◧]`」，中间/偏左显示当前文档名与 `*` 未保存标记，右侧由 Windows 原生 `titleBarOverlay` 承接最小化/最大化/关闭按钮。
  - 无常驻富文本工具栏，无第二层原生菜单条。
- **Typora Light 色彩与排版（用户决定 + 细节建议）**：
  - **[设计建议]** 画布纯白 `#ffffff`，顶栏纯白/极浅灰无缝衔接，侧边栏极浅灰 `#f7f7f7`，分割线 `#eaecef`，正文深炭灰 `#333333`，代码块淡灰背景 `#f6f8fa`。
  - **6 级标题层级（用户决定）**：
    - **H1 / H2 / H3**：配备底部细分隔线与正文明确区分（H1、H2 分隔线清晰，H3 分隔线更轻柔），字号逐级递减，上下留白均衡。
    - **H4 / H5 / H6**：不加底部画线，通过字号、字重与柔和色阶自然区分，任意点击或框选不产生突兀跳动。

### 5.3 核心功能交互规范

#### 1. 编辑器双模式宿主与微交互（P0 + 用户决定）
- **所见即所得模式（默认）**：
  - 支持标准 Markdown 快捷输入规则（`# `–`###### `、`- `、`1. `、`- [ ] `、`> `、```` ``` ````、`**粗体**`、`*斜体*`、`` `行内代码` ``）与常用快捷键（`Ctrl+B/I/K/S/O/N/Z/Y`）。
  - **极简微交互（无常驻工具栏）**：
    - **表格创建与编辑**：可通过菜单「插入 → 表格」或快捷键插入默认 3×3 表格；光标进入表格时仅在表格顶部边缘浮现极简操作条（增删行列、左/中/右对齐），移出立即隐藏。
    - **代码块语言选择**：悬停或光标进入围栏代码块时，右上角显示极淡的语言输入/选择标签（可直接切换为 `mermaid` 或其他代码语言）。
    - **链接与图片属性**：`Ctrl+K` 或点击链接/图片时弹出克制的轻量小气泡编辑 URL 与说明文字；外部 `http/https` 链接通过 `Ctrl+点击` 在系统默认浏览器中打开。
- **轻量源代码模式（`Ctrl+/`，用户决定）**：
  - 按 `Ctrl+/`（或菜单项）在 Milkdown 所见即所得视图与等宽纯文本源代码编辑区之间一键切换。
  - 切换时同步当前 Markdown 文本并保持文档脏状态（`*`）一致，尽量保留大致滚动比例；两种模式各自维护独立的撤销边界，避免跨模式撤销状态错乱。
  - 源代码模式同时作为编辑 YAML Frontmatter、复杂嵌套 HTML 片段与精细调整原始 Markdown 格式的兜底出口。

#### 2. 真实文档兼容：YAML Frontmatter 与安全 HTML（用户决定）
- **YAML Frontmatter**：
  - 打开文件时识别头部 `--- ... ---` YAML 块并原样保存其原始文本，保存回写时无损拼回文档开头，绝不被解析器破坏。
  - 在所见即所得视图顶部以极低存在感的折叠条展示（默认收起，点击可查看，需修改时可切到 `Ctrl+/` 源代码模式或展开编辑）。
- **常见阅读类原生 HTML**：
  - 通过自定义 Remark/ProseMirror HTML 节点支持安全渲染日常文档高频标签（`<img width/height/src>`、`<details>/<summary>`、`<br>`、`<div/p align>`、`<sub>/<sup>`、`<kbd>`），HTML 注释（`<!-- ... -->`）无损保留不渲染占位。
  - 渲染前强制经 `DOMPurify` 严格过滤（禁用 `<script>`、`<iframe>` 及所有 `on*` 事件属性），并将原生 `<img>` 的本地相对路径同样改写为受控本地图片协议以正确显示。

#### 3. 大纲与文件树侧边栏（P1）
- **[设计建议]** 侧边栏顶部采用「文件 / 大纲」双标签切换（贴近 Typora 默认风格），并支持快捷键（`Ctrl+Shift+L`）一键折叠隐藏。
- **文件树**：
  - 打开本地文件夹后展示目录树与 `.md` / `.markdown` 文件列表；单击切换文档；支持将 `.md` 文件直接拖入窗口打开。
  - 切换文档或关闭窗口前，若有未保存修改，弹出保存 / 放弃 / 取消确认框。
  - **[设计建议]** 磁盘文件被外部程序修改时，顶部弹出温和的非打断提示条（重新加载 / 忽略），不静默覆盖当前编辑。
- **大纲**：
  - 监听文档结构变化（轻量防抖）实时提取 H1–H6 标题树（按层级缩进）。
  - 点击大纲项平滑滚动到对应标题；正文滚动阅读时自动高亮当前所在章节。

#### 4. Mermaid 流程图（P2）
- 识别语言为 `mermaid` 的围栏代码块，通过自定义 ProseMirror NodeView 实现双态体验：
  - **阅读态（失焦）**：渲染为居中、自适应宽度的清晰 SVG 图表，融入正文排版。
  - **编辑态（点击进入）**：展开简洁等宽代码编辑区，下方实时（防抖约 300ms）预览渲染结果；光标离开块区域或按 `Esc` 收起代码回到纯图表视图。
  - **容错机制**：语法不完整或有误时在预览区展示温和的错误提示，保留代码内容不丢失，不影响文档其余部分。

#### 5. GFM 表格（P3）
- 基于 Milkdown GFM preset 实现所见即所得渲染与单元格内平滑编辑（`Tab` / `Shift+Tab` 切换单元格），配合上述极简悬浮操作条完成增删行列与对齐设置。

#### 6. 轻量页内查找（`Ctrl+F`，用户决定）
- 按 `Ctrl+F` 在编辑区右上角滑出极简查找浮条（关键词输入框、匹配计数 `当前/总数`、上一个/下一个按钮、`Esc` 关闭）。
- 所见即所得模式下桥接主进程 `webContents.findInPage` / `stopFindInPage`；不包含替换功能（`Ctrl+H` 留待后续版本）。

#### 7. 导出 PDF（P4）
- 通过菜单或快捷键触发，切换至打印专用 `@media print` 样式：
  - 自动隐藏顶栏、侧边栏、查找条与各类交互浮层；
  - 正文适配 A4 页边距，保留与屏幕一致的 H1–H3 底线、字号层级、代码块、表格、安全 HTML 与 Mermaid SVG；
  - 控制分页合理性（标题尽量不孤立在页尾 `break-after: avoid`，代码块与 Mermaid 图表尽量避免被生硬截断 `break-inside: avoid`）。
- 由主进程调用 `webContents.printToPDF()` 生成并保存到用户选定路径。

## 6. 留给实施者决定的事项
