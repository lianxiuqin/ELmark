> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Model Strategy Note:** Per user request, this plan is structured into small, strictly-typed, TDD-verified tasks with locked `Interfaces` blocks so implementation subagents can run on a lower-cost model (e.g. `flash` / Gemini 4 H tier) without guesswork, while each task's tests + fresh review gate verify correctness before proceeding.

**Goal:** Build ELmark V1, a free, non-infringing, Typora Light-style desktop Markdown reader and editor on Electron + Node.js using Milkdown headless core (`@milkdown/kit`), with File Tree & Outline sidebar, Mermaid diagrams, GFM tables, YAML Frontmatter preservation, safe HTML rendering, lightweight Source Mode (`Ctrl+/`), `Ctrl+F` find bar, and PDF export.

**Architecture:** Standard three-process Electron app (`electron-vite` + TypeScript + React): Node.js Main Process handles native windowing (`titleBarStyle: 'hidden'` + `titleBarOverlay`), filesystem/directory tree, external file watching,受控 `elmark-local://` image protocol, `Menu.popup()`, `findInPage`, and `printToPDF`; Preload exposes a minimal typed `window.elmark` bridge via `contextBridge`; Renderer hosts a dual-mode editor (`@milkdown/kit` WYSIWYG ↔ monospace Source Mode) with pure testable modules for Frontmatter, `DOMPurify` HTML sanitization, image URL rewriting, and Outline extraction.

**Tech Stack:** Electron 31+, Node.js v24+, `electron-vite`, Vite, React 18, TypeScript 5, `@milkdown/kit`, `@milkdown/react`, `mermaid`, `dompurify`, `lowlight` / `highlight.js`, Vitest, `@testing-library/react`, `jsdom`.

**Spec:** [docs/superpowers/specs/2026-11-27-elmark-design.md](../../specs/2026-11-27-elmark-design.md)

## Global Constraints

- Platform: Windows 10/11 desktop first, Node.js `v24.21.0` / npm `11.19.0`, PowerShell-safe commands (`;` instead of `&&` when chaining in Windows PowerShell 5.1).
- Security: `contextIsolation: true`, `nodeIntegration: false`, all native HTML sanitized through `DOMPurify` (no `<script>`, `<iframe>`, `on*`, or `javascript:` URLs), local images served exclusively via controlled `elmark-local://` protocol.
- Licensing & Anti-plagiarism: MIT / Apache-2.0 / BSD / ISC dependencies only; zero copied Typora source, CSS, icons, or proprietary fonts.
- Data integrity: Local UTF-8 `.md` files are the sole source of truth; YAML Frontmatter (`--- ... ---`) must never be corrupted on save.
- Visual & UX non-negotiables: Typora Light palette (`#ffffff` canvas, `#f7f7f7` sidebar, `#333333` text, `#eaecef` borders, `#f6f8fa` code blocks), H1–H3 bottom borders, H4–H6 typographic hierarchy without borders, zero MarkText-style raw `#` jumping on heading click/selection, no persistent formatting toolbar or Notion drag handles, single unified Windows top bar (`titleBarStyle: 'hidden'` + `titleBarOverlay`).
- V1 Non-Goals (do not build): `Ctrl+H` find-and-replace, multi-tab UI, LaTeX/KaTeX math, cloud sync, plugin/theme store, image host upload.

## Review Focus

1. **Windows CRLF (`\r\n`) & horizontal rule (`---`) vs YAML Frontmatter** — A `.md` file with `\r\n` endings or starting with a `---` thematic break (no closing `---` YAML block) must not be misparsed or truncated on `splitFrontmatter`/`joinFrontmatter`. *(Pinned in Task 3)*
2. **XSS payload & Chinese/spaced Windows relative paths in native HTML** — `<img src="./图 片/a.png" width="400" onerror="alert(1)">` and `<script>alert(1)</script>` must strip all executable code while keeping `width="400"` and encoding the local path cleanly into `elmark-local://`. *(Pinned in Task 4)*
3. **Hash comments inside fenced code blocks polluting Outline** — `# comment` or `## heading` inside ```` ```python ```` or ```` ```mermaid ```` blocks must never show up in the Outline sidebar. *(Pinned in Task 5)*
4. **External watcher false alarm on self-save & dirty-guard safety** — Saving via `Ctrl+S` must suppress `fs.watch` self-triggered events so the "文件已在外部修改" banner never flashes after the user's own save; switching files with unsaved edits must invoke the save/discard/cancel guard. *(Pinned in Task 2 & Task 9)*
5. **Broken Mermaid syntax & WYSIWYG ↔ Source Mode round-trip** — Invalid Mermaid code must render an inline error state without crashing React/ProseMirror or losing source text; toggling `Ctrl+/` WYSIWYG → Source → WYSIWYG must preserve Frontmatter, Mermaid, Tables, and dirty state accurately. *(Pinned in Task 7 & Task 9)*
